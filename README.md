# AI Travel — AI Travel Itinerary Builder

A full-stack web app that turns a traveler's preferences (origin, destination,
dates, budget, travelers, and travel "vibes") into a realistic, structured,
day-by-day trip plan — flights, accommodation, food, activities, backup
options, and a budget breakdown — generated by an AI model and grounded in
real destination distance/weather data.

---

## 1. What the project does

You fill out a trip-planning form. The backend:

1. Estimates flight cost/duration from real geographic distance between your
   origin and destination.
2. Estimates accommodation pricing bands for the destination.
3. Looks up real (or seasonally-estimated) weather for your travel dates.
4. Sends all of that, plus your preferences, to an AI model, which returns a
   structured JSON itinerary: day-by-day schedule, restaurants, backup plans,
   and a budget breakdown that's been optimized to fit your budget.
5. Renders it all as a polished, boarding-pass-themed results page.

If the AI itinerary would exceed your budget, the AI is instructed to swap in
cheaper alternatives and explain what it changed — you'll see that note on
the results page.

## 2. Features

- Multi-select "travel vibe" chips (Adventure, Food, Relaxing, Culture,
  Nature, Shopping, Nightlife, Luxury, Budget, Family-friendly)
- Distance-based **estimated** flight pricing (clearly labeled — not live
  airline data)
- Destination-tiered **estimated** accommodation pricing
- Real short-range weather forecast (Open-Meteo) when your trip is within
  ~15 days, or a seasonal climate estimate otherwise
- AI-generated day-by-day itinerary with per-activity costs and "why this
  fits your vibe" explanations
- Automatic budget optimization with an explanation when the plan is
  adjusted to fit
- Backup options for weather/availability-sensitive activities
- A "beautiful loading" experience with rotating status messages
- Full client + server-side validation (dates, budget, required fields)
- **Demo/fallback mode**: works out of the box with sample data even with no
  API keys configured, so it's always demonstrable

## 3. Technology stack

**Frontend:** HTML5, CSS3, vanilla JavaScript (no frameworks/build step)
**Backend:** Python 3, Flask
**AI:** Anthropic Messages API (`anthropic` Python SDK)
**Weather/geocoding:** Open-Meteo (free, no API key required)
**Flight/hotel data:** distance-based heuristic estimates (see §12 for
swapping in a real provider)

## 5. Install Python (Windows)

1. Download Python 3.11+ from https://www.python.org/downloads/
2. During install, **check "Add python.exe to PATH"**.
3. Verify in PowerShell or Command Prompt:
   ```
   python --version
   ```

## 6. Create a virtual environment (Windows)

Open PowerShell in the project folder (`AI-Travel/`) and run:

```
python -m venv venv
venv\Scripts\activate
```

Your prompt should now start with `(venv)`. (macOS/Linux equivalent:
`python3 -m venv venv && source venv/bin/activate`.)

## 7. Install dependencies

With the virtual environment activated:

```
pip install -r requirements.txt
```

## 8. Configure environment variables

Copy the example file:

```
copy .env.example .env
```

*(macOS/Linux: `cp .env.example .env`)*

Open `.env` in a text editor and fill in `ANTHROPIC_API_KEY` (see §11). You
can leave it blank to run in demo mode first.

## 9. Start the Flask server

From the project root (`AI-Travel/`), with the virtual environment active:

```
python backend\app.py
```

*(macOS/Linux: `python backend/app.py`)*

You should see:

```
AI Travel backend starting on http://localhost:5000 (debug=True)
```

## 10. Open the application

Go to **http://localhost:5000** in your browser. Flask serves the frontend
directly — there's no separate frontend server or build step.

## 11. Configure the AI API

This project uses the Anthropic API.

1. Create an account and API key at https://console.anthropic.com/settings/keys
2. Put it in `.env`:
   ```
   ANTHROPIC_API_KEY=your-real-key-here
   ```
3. Restart the Flask server.

Without a key, the app runs in **demo mode**: it still works end-to-end, but
returns clearly-labeled sample itinerary data instead of a live AI
generation. You'll see a "Demo mode" banner on the results page and a
console log line when the server starts.

The model used is controlled by `ANTHROPIC_MODEL` in `.env` (defaults to
`claude-sonnet-5`). Check https://docs.claude.com for the current list of
available model names if you hit a "model not found" error — model names
are occasionally renamed/retired.

## 12. Configure optional travel/weather APIs

- **Weather** uses Open-Meteo, which is free and requires no signup or key.
  Nothing to configure.
- **Flights/hotels**: there is no free, keyless, production-grade flight or
  hotel pricing API, so this project estimates prices from real distance and
  destination-tier data instead of faking "live" numbers. If you have access
  to a real provider (e.g. the Amadeus Self-Service API), you can:
  1. Add your credentials to `.env` as `TRAVEL_API_KEY` (already stubbed in
     `.env.example`).
  2. Implement the real API call inside
     `backend/services/travel_service.py`, in `get_flight_estimate()` and
     `get_accommodation_estimate()`, keeping the same return shape so the
     rest of the app doesn't need to change.

## 13. How demo/fallback mode works

Every external dependency degrades gracefully instead of crashing:

| Dependency | If unavailable |
|---|---|
| `ANTHROPIC_API_KEY` missing | `ai_service.py` returns a clearly-labeled sample itinerary instead of calling the API |
| Weather lookup fails / destination not found | `weather_service.py` returns `"source": "unavailable"` with a plain-language note; the AI is told weather data is unavailable |
| Flight/hotel geocoding fails | `travel_service.py` returns `"available": false` with a note; the AI works around it |
| AI returns malformed JSON | `ai_service.py` raises a handled error → the frontend shows the "We hit some turbulence" error screen with a Try Again button, never a stack trace |

This means the app is always demonstrable, even fully offline for the UI
flow (though weather/geocoding calls will simply report "unavailable"
without internet access).

## 14. How to test the application

1. Start the server (§9) and open http://localhost:5000.
2. Fill in the form — try Karachi → Istanbul, pick a few dates within the
   next 2 weeks (to see a real weather forecast), set a budget, and select
   1–3 vibes.
3. Click **BUILD MY TRIP** and watch the loading sequence.
4. On the results page, check that: total cost / remaining budget / percent
   used are consistent with the budget bar, and check each section renders
   (flight, accommodation, day-by-day, restaurants, backups, tips).
5. Try an intentionally invalid submission (e.g. return date before
   departure) to confirm you get a friendly inline error, not a crash.
6. Try it with no `ANTHROPIC_API_KEY` set to confirm demo mode works, then
   add a real key and confirm you get a live, budget-aware AI itinerary.

## 15. Data flow: frontend → Python → APIs/AI → frontend

```
script.js (fetch)
   │  POST /api/generate-trip  { origin, destination, dates, budget, ... }
   ▼
backend/app.py
   │  validates request (dates, budget, required fields)
   │
   ├─► travel_service.get_flight_estimate()       (geocoding + distance heuristic)
   ├─► travel_service.get_accommodation_estimate() (destination-tier pricing)
   ├─► weather_service.get_weather()               (Open-Meteo forecast/seasonal)
   │
   ▼
ai_service.generate_itinerary(trip_input, flight_data, hotel_data, weather_data)
   │  builds a structured prompt, calls Anthropic Messages API (or returns
   │  demo data if no API key), parses + validates the JSON response
   ▼
backend/app.py
   │  returns { itinerary, meta, raw_supporting_data } as JSON
   ▼
script.js
   │  renders trip header, budget bars, flight/stay cards, day-by-day
   │  timeline, restaurants, backups, and tips into the results view
   ▼
Browser UI
```

## 16. Common errors and fixes

| Symptom | Likely cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named 'flask'` | Dependencies not installed, or venv not activated | Run `venv\Scripts\activate` then `pip install -r requirements.txt` |
| Page loads but "BUILD MY TRIP" does nothing / network error | Server isn't running, or you opened `index.html` directly as a file instead of via `http://localhost:5000` | Start the server with `python backend\app.py` and use the `localhost` URL, not `file://` |
| "We hit some turbulence" every time | Check the terminal running Flask for the real error (it's not shown to the browser on purpose) | Common cause: invalid/expired `ANTHROPIC_API_KEY`, or a renamed model — check `ANTHROPIC_MODEL` in `.env` |
| Results page shows a "Demo mode" banner even though you set a key | `.env` wasn't loaded (wrong file name/location) or server wasn't restarted after editing it | Confirm the file is named exactly `.env` in the project root, then stop and restart `python backend\app.py` |
| Weather section says "unavailable" | No internet access, or the destination text couldn't be geocoded | Try a more specific destination (e.g. "Lahore, Pakistan" instead of "there"); this is a soft failure and won't break the rest of the itinerary |
| `pip install` fails on Windows with a build error | Rare with these pinned dependencies, but usually a missing C build toolchain for an unrelated package | Make sure you're using the pinned `requirements.txt` versions and a recent Python 3.11+/3.12 |
| Port 5000 already in use | Another process (or macOS AirPlay Receiver) is using port 5000 | Set `PORT=5001` (or any free port) in `.env` and restart |
